# 缓存相关

## 缓存问题

### **一、缓存雪崩（Cache Avalanche）**
#### **1. 什么是缓存雪崩？**
- **定义**：大量缓存数据在**同一时间过期**，导致所有请求瞬间穿透缓存，直接打到数据库，数据库压力骤增甚至崩溃。
- **类比**：快递仓库里所有货物同时到期被清空，所有人直接去工厂抢货，工厂瘫痪。

#### **2. 举例场景**
- **例子**：电商首页有 1000 个商品的缓存，设置统一过期时间 24 小时。第二天零点缓存同时失效，大量用户请求直接访问数据库，导致数据库崩溃。

#### **3. 解决方案**
- **核心思路**：避免缓存集中过期，分散风险。
- **具体方法**：
  1. **随机过期时间**：给每个缓存设置基础过期时间 + 随机偏差（如 `24h + 随机0-2h`）。
  2. **缓存永不过期**：由后台异步更新缓存（例如定时任务或消息队列触发更新）。
  3. **多级缓存**：使用本地缓存（如 Caffeine） + Redis 缓存，多层兜底。
  4. **熔断降级**：数据库压力过大时，启动限流（如每秒只放行 1000 个请求）。

### **二、缓存击穿（Cache Breakdown）**
#### **1. 什么是缓存击穿？**
- **定义**：某个**热点数据过期**的瞬间，大量并发请求直接穿透缓存访问数据库，导致数据库压力激增。
- **类比**：爆款商品突然缺货，所有人挤到工厂门口抢购，工厂服务器崩溃。

#### **2. 举例场景**
- **例子**：微博热搜榜的 Top1 新闻缓存过期，瞬间有 100 万用户同时请求该数据，数据库被击穿。

#### **3. 解决方案**
- **核心思路**：避免单个热点数据失效时被高并发击穿。
- **具体方法**：
  1. **互斥锁（Mutex Lock）**：
     - 第一个请求发现缓存失效时，加锁（如 Redis 的 `SETNX` 命令）。
     - 只有拿到锁的线程去数据库加载数据，其他线程等待。
     ```java
     public String getData(String key) {
         String data = redis.get(key);
         if (data == null) {
             if (redis.setnx(key + "_lock", "1", 10)) { // 加锁
                 data = db.get(key);                    // 查数据库
                 redis.set(key, data, 60);              // 写缓存
                 redis.del(key + "_lock");              // 释放锁
             } else {
                 Thread.sleep(100);                     // 等待重试
                 return getData(key);                   // 重试获取缓存
             }
         }
         return data;
     }
     ```
  2. **逻辑过期**：缓存永不过期，但在缓存中存储数据的**逻辑过期时间**，由异步线程更新。
  3. **热点数据预加载**：提前预测热点数据（如秒杀商品），在过期前主动刷新。

### **三、缓存穿透（Cache Penetration）**
#### **1. 什么是缓存穿透？**
- **定义**：请求访问数据库中**根本不存在的数据**，缓存和数据库都查不到，导致每次请求都直接访问数据库。
- **类比**：有人用不存在的订单号反复查询，快递仓库和工厂都找不到，但查询请求一直堆积。

#### **2. 举例场景**
- **例子**：攻击者用随机生成的用户 ID（如负数或超大数）频繁请求，绕过缓存直接查询数据库。

#### **3. 解决方案**
- **核心思路**：拦截无效请求，避免穿透到数据库。
- **具体方法**：
  1. **缓存空值（Cache Null）**：
     - 数据库查不到的数据，在缓存中存储空值（如 `key: null`），并设置较短过期时间（如 5 分钟）。
     ```java
     public String getData(String key) {
         String data = redis.get(key);
         if (data != null) {
             return data.equals("NULL") ? null : data; // 处理空值
         }
         data = db.get(key);
         if (data == null) {
             redis.set(key, "NULL", 300);            // 缓存空值
             return null;
         }
         redis.set(key, data, 3600);
         return data;
     }
     ```
  2. **布隆过滤器（Bloom Filter）**：
     - 在缓存前加一层布隆过滤器，快速判断数据是否存在。
     - 如果布隆过滤器认为数据不存在，直接返回，无需查询缓存和数据库。
     - 缺点：布隆过滤器有误判率（可能把存在的误判为不存在）。
  3. **接口校验**：对请求参数做合法性检查（如 ID 必须为正整数）。

### **四、三者的区别总结**
| **问题**       | **触发条件**               | **后果**                     | **解决方案**                  |
|----------------|--------------------------|----------------------------|-----------------------------|
| **缓存雪崩**   | 大量缓存同时过期            | 数据库瞬间压力过大             | 随机过期时间、多级缓存、熔断降级   |
| **缓存击穿**   | 单个热点数据过期            | 高并发请求击穿数据库            | 互斥锁、逻辑过期、预加载热点数据   |
| **缓存穿透**   | 查询不存在的数据            | 缓存和数据库均无效，资源浪费     | 缓存空值、布隆过滤器、参数校验     |

---

### **五、实战建议**
1. **组合使用**：例如用布隆过滤器防穿透 + 互斥锁防击穿 + 随机过期时间防雪崩。
2. **监控工具**：使用 Redis 的 `INFO` 命令或监控工具（如 Prometheus）观察缓存命中率。
3. **压测验证**：用 JMeter 模拟高并发场景，测试解决方案是否有效。
