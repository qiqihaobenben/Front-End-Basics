# Linux 启动过程：从电源按钮到内核

## 第一部分——从电源按钮到内核的初次呼吸

你按下电源按钮。一秒后，文字墙滚动而过，或标志渐显，最终 Linux 系统出现。其间发生的一切并非魔法，而是微小程序与物理 CPU 之间精密的握手过程。本部分将追踪这个握手过程，直至 Linux 内核中第一行 C 代码开始运行。

### The very first instruction

当电源稳定后，CPU 会自动重置为一种名为实模式的微小、古老运行模式。实模式可追溯至最初的 8086 芯片。其规则刻意设计得极为简单：内存地址由 CPU 存储在名为寄存器的特殊高速存储器中的两个数值构成。具体组合方式如下：

将段地址与偏移量结合：

```
physical_address = (segment << 4) + offset
```

若看到类似 `0xFFFFFFF0` 的数字，那便是十六进制。十六进制是以 16 为基数的计数系统。我们在前面添加 `0x` 标记以明确其性质。 `0x10` 在日常计数中代表 16， `0x100000` 则表示 1 兆字节。十六进制与硬件存储位的方式高度契合，因此在底层代码中随处可见其踪影。

复位后，CPU 会立即跳转至一个名为复位向量（reset vector）的特殊地址 `0xFFFFFFF0` 。可将其视为一个永久书签，标注着"由此开始"。该地址几乎没有存储空间，因此制造商在此处设置了一个远跳转指令，将控制权移交至主板固件。

> 简明说明：寄存器，寄存器是 CPU 内部的微型存储单元，用于存放 CPU 当前正在使用的数值。诸如 CS 和 IP 这类名称即为寄存器名称。CS 代表"代码段"，标记当前指令所在的区域；IP 代表"指令指针"，标记接下来要执行的指令。

### BIOS 和 UEFI

固件是预先烧录在电路板上的小型启动程序。

BIOS（Basic Input Output System） 即基本输入输出系统，属于较早的架构。它会执行名为 POST 的快速健康检测，检查启动顺序并逐个尝试设备。若发现磁盘首个 512 字节扇区以标记字节 `0x55` 和 `0xAA` 结尾，则将该设备视为可启动设备。 BIOS 将该扇区复制到内存地址 `0x7C00` 并跳转至该位置。由于该扇区体积微小，通常仅包含加载后续较大数据块的指令。

UEFI（Unified Extensible Firmware Interface，统一可扩展固件接口）是现代替代方案。它依然负责启动机器，但能直接理解文件系统，无需通过旧式"第一扇区"操作即可加载更大的启动程序。UEFI 还能向操作系统传递更丰富的信息。

它们两者，路径不同，目标相同：将控制权移交给能加载 Linux 的启动程序。

### 引导加载程序（Bootloader）

引导加载程序如同引路人，负责将操作系统就位。GRUB 是个人电脑上广受欢迎的选择。它读取配置文件，若安装了菜单则显示出来，GRUB 菜单会显示所有可启动的操作系统，用户可以选择要启动的操作系统，并将 Linux 内核加载到内存中。Linux 内核文件实际上包含两部分：

- 一个小型设置程序，仍能在实模式下运行
- 稍后将被解压的较大压缩内核

GRUB 还会填充一个名为设置头的小型结构体，其中包含实用信息：内核的存放位置、命令行的所在位置，以及初始化文件（若存在）的存放位置。随后它便跳转至设置程序。

### 设置程序（Setup Program）会创建一个安全房间

在 Linux 能执行任何有意义的操作之前，初始化代码会创建一个可预测的工作空间。

它将段寄存器对齐，确保内存复制操作每次行为一致。此处出现的名称包括：CS 代表代码段、DS 代表数据段、SS 代表栈段。同时它还会清除名为"方向标志"的 CPU 位，使复制指令能向前遍历内存。

它清空了一个名为 BSS 的区域。BSS 区域存放必须初始化为零的全局变量。C 语言假定 BSS 区域为零。初始化程序会将整个区域覆盖为零，以确保这一特性。

若在内核命令行传递了 `earlyprintk` 参数，设置代码还会编程串口以便其能输出早期消息。当图形界面尚未就绪时，此功能尤为实用。

最后，设置程序会询问固件"我们实际拥有多少可用内存，以及内存中存在哪些缺口"。在旧版 BIOS 中，这通常被称为 e820 调用，它会返回一个简单的可用和保留内存区域列表。内核将利用该列表来避免与固件功能发生冲突。

完成上述操作后，初始化代码调用其首个 C 函数，该函数的字面名称为 main 。此时系统仍处于旧式实模式。接下来的任务便是退出该模式。

> 简明说明：中断，中断是硬件或软件发出的"打断"信号，它会暂停 CPU 当前任务，并为紧急事件运行小型处理程序。定时器执行是中断，按键操作也是中断。

中断分为两类：

- 可屏蔽中断遵循用户规则，可在关键时刻临时阻塞以避免触发；
- 不可屏蔽中断（常称 NMI）则始终生效，因其通常报告严重硬件问题。 不可屏蔽中断（常称 NMI）则始终会插入系统，因为它们通常报告严重的硬件问题。我们将通过模式切换控制这两类中断，确保运行过程中不会遭遇意外中断。

## 第二部分——告别实模式，踏入 32 位领域，抵达 64 位世界

现代个人电脑上的 Linux 系统运行于长模式，即 x86_64 架构的 64 位模式。无法从实模式直接跳转至该模式，需依次经历实模式 → 保护模式 → 长模式的过渡路径。本节将阐述该路径并解释相关术语。

### 保护模式，抛开术语迷雾

保护模式是为突破 1980 年代的限制而引入的 32 位世界。它增添了两个核心理念。

全局描述符表（GDT）是一份简短的分段描述清单。每条描述都说明"该分段从这里开始，覆盖此范围，并允许执行这些操作"。Linux 对此保持简洁，采用扁平化模型——这意味着基址为零，分段大小覆盖整个 32 位空间。当所有分段扁平化后，地址又重新呈现为纯数字形式。

中断描述符表（IDT）如同紧急呼叫的"电话号码"目录。当中断发生时，CPU 会查询 IDT 中的条目，并跳转至该条目所列的中断处理程序。在切换过程中，我们会加载一个微型占位 IDT，因为此时本就要屏蔽中断。待真实内核接管后，功能完整的 IDT 才会随后加载。

### 谨慎的切换

初始化代码首先关闭噪声源。它通过单条指令禁用可屏蔽中断，暂时完全阻断硬件中断，使老式 PIC 芯片静默。接着开启 A20 线路——这是历史遗留特性：早期 PC 在 1MB 处发生地址溢出，开启 A20 可消除溢出，使高地址段正常工作。最后重置数学协处理器，确保浮点状态归零。

随后加载一个仅包含当前所需内容的微型全局数据表（GDT）和一个微型中断数据表（IDT）。最后在名为 CR0 的控制寄存器中设置一个名为 PE 的单比特，并执行远跳转。该跳转从 GDT 重新加载代码段并锁定保护模式，同时重新加载数据段与栈段，并将栈指针固定为匹配新的扁平化内存空间。

我们现在处于 32 位保护模式。

简明说明：控制寄存器 CPU 拥有若干用于开关控制的特殊寄存器。CR0 用于启用保护模式。CR3 存储页表顶部的地址，我们稍后将用到它。CR4 则启用一系列扩展功能，例如更大的页表条目。

### 为什么我们还没完成

Linux 需要 64 位支持。这便是长模式。需要两项条件。

分页功能必须开启。分页机制是虚拟地址与物理地址之间的转换器。程序使用虚拟地址，而硬件读写物理内存。页表通过称为页的固定大小块将两者相互映射。在个人计算机上，标准页为 4 千字节，也存在更大容量的页。系统启动初期，内核会使用 2 兆字节的页快速描述低内存区域。

必须设置名为 EFER 的特殊寄存器中的一个位（称为 LME），才能启用长模式。EFER 是型号特有的寄存器，这其实就是说"用于特定 CPU 功能的寄存器"。

### 构建恰到好处的分页

32 位程序导入段构建了一组小型页表，其中规定“对于该区域，虚拟地址等同于物理地址”。这种映射称为恒等映射。仅此便足以安全地启用分页功能。

为实现此功能，代码在 CR4 中启用 PAE，从而使用更大的条目。它构建了一组覆盖低内存的最小表集，每块为 2 兆字节。它将顶部表的地址写入 CR3。分页功能现已就绪。

最后，它将 LME 设置为 EFER 模式，并执行远跳转至以 64 位代码书写的标签。长模式现已激活。段地址仍为"平坦"模式，但地址和寄存器均为 64 位宽。

为何如此谨慎？在运行中的系统切换模式，犹如在疾驰中更换车轮。代码会中断操作，准备最低限度的所需表，翻转位，然后才重新启用中断。缓慢而稳妥的操作，可避免出现半切换的怪异状态。

## 第三部分——解析真实内核、修复地址，以及 Linux 为何会自行迁移

我们拥有一个启用分页功能的 64 位 CPU，内存中存放着压缩内核。现在，这个小巧的 64 位跳转程序承担实际工作：必要时让出空间，解压内核，若内核未位于默认位置则修正地址，最后执行跳转。

它会清除自身的 BSS，因此全局状态将从干净状态开始。

它加载了一个包含两个处理程序的最小化中断描述表（IDT）。一个用于页面故障，另一个用于非屏蔽中断（NMI）。当 CPU 无法为尝试使用的虚拟地址找到映射时，就会发生页面故障。在我们早期基于标识映射的系统中，微小的页面故障处理程序能够即时添加缺失的映射并继续运行。NMI 处理程序的存在，是为了确保在系统初始化阶段，非屏蔽中断不会导致机器崩溃。

它还会为即将访问的区域构建标识映射。这包括内核的未来驻留位置、引导加载程序填充的小型引导参数页，以及命令行缓冲区。

一个通常命名为 `extract_kernel` 的 C 函数接管处理。它为临时缓冲区分配一小块堆内存，打印经典提示语，并使用内核构建时采用的算法进行解压。gzip、xz、zstd、lzo 等压缩工具均可接入同一个封装器。

当字节数据读取完毕后，解压缩器会读取内核的 ELF 头部信息。ELF（可执行与可链接格式）既是一种文件格式，也是一种映射表。它标明了哪些区块属于代码、哪些属于数据，以及每个区块的确切存储位置。解压缩器会将每个区块复制到其对应的位置。

如果内核在与编译时不同的地址加载，解压缩器会应用重定位操作。重定位是一种小修补程序，用于调整包含地址的指针或指令。解压缩器遍历这些重定位项的列表，逐个修补每个位置，使其指向实际使用的地址空间中的正确位置。

当一切就绪后，解压器返回真实内核的入口点并跳转至此处，同时传递引导参数的指针。自此你便进入完整内核。首个遇到的函数是 `start_kernel` ，大规模初始化随即启动。

### 为什么内核有时会故意移动自身

您可能会在内核日志中看到 kASLR 的提及。该缩写代表内核地址空间布局随机化（Kernel Address Space Layout Randomization）。其原理很简单：若攻击者无法确定内核在内存中的具体位置，某些攻击手段的实施难度将大幅增加。

在启动早期，若启用了 kASLR，解压缩器会随机选择两个“基址”：

- 物理基础，即字节在 RAM 中的存放位置
- 虚拟基址，即内核在完成完整分页设置后将使用的起始虚拟地址

它会建立一个禁止触碰的列表。该列表包含解压缩器本身、压缩映像、初始 RAM 磁盘、引导参数页面以及命令行缓冲区。您还可通过命令行中的 `memmap=` 选项预留特定范围区域加入此列表。

它扫描固件的内存映射以寻找大型空闲区域。对于每个空闲区域，它计算能容纳多少个正确尺寸的对齐"插槽"。它使用最佳早期熵源生成随机数。 在现代 CPU 上，这可能是硬件随机指令。它将数值缩减至槽位总量，并选取匹配的槽位作为物理基址。虚拟基址采用相同方式选取，但限定在内核虚拟地址窗口范围内。

若不存在合适的地址，程序将回退至默认地址并输出简短警告。若在命令行传递 `nokaslr` 参数，则按设计跳过随机化步骤。

## 一个可收藏的速查词汇表

#### Hexadecimal 十六进制

十六进制数以 `0x` 表示。 `0x10` 表示 16， `0x100000` 表示 1 兆字节。十六进制能精确映射至位，因此底层代码常采用此表示法。

#### Register 寄存器

CPU 内部一个微小的槽位，当前存储着某个数值。例如：CS（代码段寄存器）、DS（数据段寄存器）、SS（栈段寄存器）、IP（指令指针寄存器）、SP（栈指针寄存器）。

#### Segment and offset 段和偏移量

构建实模式地址的两个组成部分。物理地址等于段乘以 16 再加偏移量。

#### BIOS 基本输入输出系统

一种较旧的固件，用于启动机器、检测硬件，并将第一个引导扇区加载到内存中（加载操作系统）。BIOS 是计算机硬件和软件之间的桥梁。

#### UEFI 统一可扩展固件接口

UEFI 是 BIOS 的继任者。它是一个更现代、更灵活的固件接口。UEFI 可以理解文件系统，无需通过旧式"第一扇区"操作即可加载更大的启动程序。UEFI 还能向操作系统传递更丰富的信息。

#### Bootloader 引导加载程序

引导加载程序是计算机启动时最先执行的程序，它负责将内核加载到内存中，并向其传递系统相关信息。GRUB 是常见的引导加载程序之一。

#### Stack 栈

用于函数的后进先出工作台。栈指针(SS)选择其段，栈指针(SP)指向当前栈顶。

#### BSS

存放必须初始化为零的全局变量的区域。内核初始化代码会在 C 程序运行前清空该区域。

#### Interrupt 中断

硬件或软件发出的快速“打断”。CPU 暂停运行，执行一个小型处理程序，然后继续运行。可屏蔽中断可被暂时阻塞，而无中断屏蔽功能（NMI）则不可。

#### GDT（Global Descriptor Table） 全局描述符表

分段描述符的简短列表。Linux 将其设置为简单的扁平模型。

#### IDT（Interrupt Descriptor Table） 中断描述符表

中断处理程序的目录。早期引导阶段使用精简版本，完整内核会在后续安装真正的 IDT。

#### A20 line

早期 PC 在 1MB 处发生地址溢出，开启 A20 可消除溢出，使高地址段正常工作。

#### Protected mode 保护模式

32 位模式，引入全局数据段表（GDT）和中断数据段表（IDT），并支持分页功能。

#### Long mode 长模式

x86_64 架构上的 64 位模式。需要启用分页功能，并在 EFER 寄存器中设置名为 LME 的位。

#### Paging 分页

将虚拟地址转换为物理内存的机制。通过页表实现。

#### Page Tables 页表

将虚拟页映射到物理页的数据结构。早期启动阶段使用全局映射。常规页大小为 4KB。早期启动常采用 2MB 页快速覆盖基础区域。

#### CRO，CR3，CR4 控制寄存器

CR0 用于开启保护模式。CR3 指向页表的顶部。CR4 启用扩展功能，如 PAE。

#### EFER 扩展功能寄存器

一个模型特有的寄存器，其中包含长模式使能位及其他位。

#### ELF

内核的磁盘格式，内置了文件归属位置的映射表。

#### Relocation 重定位

一种修复机制，用于在代码以不同于其编译时的基址加载时调整地址。

#### Kernel Address Space Layout Randomization (kASLR)

一种安全机制，通过随机化内核的加载地址，增加攻击者确定内核位置的难度。

在启动时随机化内核基址，以增加漏洞利用的难度。
