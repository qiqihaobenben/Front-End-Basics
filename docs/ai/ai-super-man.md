# AI 超级个体

角色 → 决策权 → 模型分工 → 工具编排

## 模型总分工建议

| 模型        | 你该怎么用                                         | 不适合做什么             |
| ----------- | -------------------------------------------------- | ------------------------ |
| **ChatGPT** | 产品抽象、系统设计、架构推演、跨角色协调、最终决策 | 超长代码生成、超严谨推理 |
| **Claude**  | 代码生成、重构、测试、文档、技术深挖               | 发散式产品创意           |
| **Gemini**  | 信息整合、多文档理解、方案校验、第二意见           | 精细工程落地             |

## 真实需要的 AI 角色

建议把角色拆成 **8 类**：

1. **产品 & 商业决策（自己 + AI）**
2. **需求分析 / PRD**
3. **UX / UI 设计**
4. **系统架构师**
5. **前后端工程**
6. **测试 / QA**
7. **运维 / DevOps**
8. **安全 / 成本 / 风险控制**

## 按角色分配“最优 AI + 工具组合”

### 产品经理 / 产品负责人

#### 推荐主模型

**ChatGPT（主） + Gemini（校验）**

**原因：**

- ChatGPT：产品抽象能力、逻辑推进、结构化 PRD 最强
- Gemini：适合做「有没有漏掉」「市场/竞品视角补充」

#### 不建议

- Claude：容易在产品阶段“过度工程化”

#### 实战用法

你可以固定一个流程：

```text
① ChatGPT：从 0 → PRD v1（目标/用户/核心流程）
② Gemini：站在「投资人 / 用户 / 市场」角度挑毛病
③ ChatGPT：收敛为 PRD v2（自己最终拍板）
```

### 设计师

#### 推荐工具组合（从“设计感”到“可交付”）

**必选：**

- **Figma + AI 插件**
- **ChatGPT（UX 逻辑）**
- **Midjourney / DALL·E / Leonardo（视觉）**

#### 角色分工建议

| 子角色                 | 用什么                |
| ---------------------- | --------------------- |
| UX 设计（流程/可用性） | ChatGPT               |
| UI 风格探索            | Midjourney / Leonardo |
| 可落地界面             | Figma + AI            |

#### 实战提示

**不要直接让 AI 出 UI**，而是这样用：

```text
1. ChatGPT：定义 UX 原则（目标用户、操作路径）
2. MJ：探索 3–5 种视觉方向
3. 自己选 1 个 → Figma AI 生成组件
4. Claude：检查前端可实现性
```

### 架构师

#### 最优组合

**ChatGPT（架构） + Claude（工程可行性）**

| 任务                | 模型    |
| ------------------- | ------- |
| 架构图 / 服务拆分   | ChatGPT |
| 技术选型 / 性能分析 | Claude  |
| 替代方案校验        | Gemini  |

**不要让 Cursor/Claude Code 直接当架构师。**

### 前后端开发

#### 推荐“主力 + 辅助”结构

- **主力写代码**：Claude Code / Cursor
- **复杂逻辑解释 & Debug**：ChatGPT 开发专家/前端专家/服务端专家 GPTs
- **大项目上下文理解**：Gemini 开发专家/前端专家/服务端专家 Prompt（偶尔）

#### 一个非常实用的原则

### 测试 / QA

这是 AI 超级擅长、但人类最容易忽略的角色。

#### 推荐方案

- **Claude：生成测试用例（强项）**
- **ChatGPT：异常路径、用户误操作**
- **Playwright / Cypress + AI**

你可以固定一个 Prompt：

> “你是一个极端挑剔的 QA，请用破坏性思维测试这个系统。”

### 运维 / DevOps

你已经在用 Claude 运维专家 Prompt / ChatGPT 运维专家 GPTs，这没问题。

补充建议：

- **用 ChatGPT 做架构决策**
- **用 Claude 写 CI/CD / Docker / Terraform**
- **加一个成本 AI 角色**

### 安全 / 成本 / 风险

3 个 AI 角色 Prompt：

1. **安全审计 AI**（漏洞、权限、数据）
2. **成本控制 AI**（云资源、API 调用）
3. **法律/合规 AI**（隐私、开源协议）

很好，这一步相当于**把“会用很多 AI 工具”升级为“可复制、可扩展、低认知负担的 AI 软件公司”**。

下面我给你的是一套**已经抽象到“长期可用”的 SOP**，不是一次性玩法；以及一张**AI 角色协作流程图（超级个体视角）**。

## 超级个体 AI 软件公司 SOP（完整可执行版）

> **定位一句话**：
> 你 = CEO / 产品负责人 / 最终决策者
> AI = 各职能部门（随叫随到、无情绪、可并行）

## SOP 总览（你只需要记住这 6 步）

```
0. 目标与约束
1. 产品定义（PM）
2. UX / 设计
3. 系统架构
4. 工程实现
5. 测试 & 安全
6. 发布 & 运维
```

**每一步只指定一个“主模型 + 校验模型”**
**你只在“收敛节点”做决策**

## Step 0：目标与约束（CEO 层，必须人工主导）

### 你要输入给 AI 的只有 4 件事

```
- 目标用户是谁
- 解决什么痛点（一句话）
- 成功标准（可量化）
- 约束条件（时间 / 成本 / 技术）
```

### 使用模型

- **ChatGPT（唯一）**

🚫 不要 Gemini

🚫 不要 Claude

> 这一层是“方向盘”，不能外包给多个模型

## Step 1：产品定义 SOP（AI 产品经理）

### 目标

输出 **PRD v1 → v2（你拍板）**

### 流程

**主模型：ChatGPT**
**校验模型：Gemini**

#### 1. ChatGPT 产出

- 用户画像
- 核心使用路径
- MVP 功能列表
- 非目标清单（非常重要）

#### 2. Gemini 校验

- 有没有漏用户
- 有没有隐含假设
- 市场是否已有成熟方案

#### 3. 你做的事

- 删除 30% 功能
- 明确 MVP 边界

**产出物**

- PRD v2（冻结）

## Step 2：UX / UI 设计 SOP（你目前缺失的关键一环）

### 目标

**“能写代码的设计”**

### 流程

**UX（逻辑）**

- 主模型：ChatGPT
- 输出：用户流程图、页面清单

**UI（视觉）**

- 工具：Midjourney / Leonardo
- 输出：风格探索（不是最终稿）

**落地设计**

- 工具：Figma + AI
- 校验：Claude（前端可实现性）

**产出物**

- 页面结构
- 组件级 UI
- 设计约束说明（颜色 / 间距 / 状态）

## Step 3：系统架构 SOP（AI 架构师）

### 目标

**低复杂度 + 可扩展**

### 模型分工

- **ChatGPT：架构设计**
- **Claude：工程可行性**
- **Gemini：方案对比（可选）**

### 固定输出清单

- 架构图
- 服务拆分
- 数据模型
- 技术选型原因（未来你会感谢自己）

**冻结点**

> 架构一旦冻结，**禁止在开发中反复推翻**

## Step 4：工程实现 SOP（AI 工程部）

### 这是你最强的一环，稍微规范一下就会非常猛

### 推荐执行结构

| 任务         | 工具                 |
| ------------ | -------------------- |
| 主写代码     | Claude Code / Cursor |
| Debug / 解释 | ChatGPT              |
| 大上下文     | Gemini（偶尔）       |

### 强制规则（非常重要）

- **模块化开发**
- **一次只实现一个用户故事**
- **每个模块必须有测试**

**产出物**

- 可运行代码
- README（Claude 自动生成）

## Step 5：测试 / QA / 安全 SOP（超级个体的护城河）

### 这是大多数独立开发者翻车的地方

### 三个 AI 角色（建议你直接保存 Prompt）

1. **破坏性 QA（Claude）**

> “你是一个恶意用户，请尽一切方式搞崩系统”

2. **异常路径专家（ChatGPT）**

> “列出所有非正常使用路径”

3. **安全 & 成本 AI（ChatGPT）**

- 权限
- 数据
- API 滥用
- 云成本

**产出物**

- 测试用例
- 风险清单
- 修复确认

## Step 6：发布 & 运维 SOP（AI 运维部）

### 模型分工

- 架构 & 决策：ChatGPT
- 脚本 & CI/CD：Claude

### 自动化目标

- 自动部署
- 自动告警
- 成本可视化

**你唯一要看的**

- 错误率
- 成本曲线
- 用户行为

## 超级个体 AI 软件公司 · 角色 Prompt 库

### CEO / 超级个体（你自己）——【方向 & 约束 Prompt】

> 用途：在一切开始之前“锁定边界”

```
你是我的战略助理。
我的身份是最终决策者，你的任务是帮我澄清目标、约束和取舍，而不是替我做决定。

项目背景：
- 产品目标：
- 目标用户：
- 核心痛点（一句话）：
- 成功标准（量化）：
- 时间约束：
- 成本约束：
- 技术或合规约束：

你的输出要求：
1. 用不超过 5 条总结项目真正要解决的问题
2. 明确【必须做 / 可以不做 / 明确不做】
3. 指出 3 个最容易失控的风险点
4. 所有内容必须简洁、可执行

禁止事项：
- 不要发散想新产品
- 不要替我做最终取舍
```

**推荐模型**：ChatGPT

### AI 产品经理 Prompt（PRD 生成）

```
你是一名资深互联网产品经理，擅长把模糊想法转化为可执行的产品方案。
请严格以 MVP 思维工作。

项目背景：
【粘贴 CEO Prompt 的输出】

你的任务：
1. 定义目标用户画像（不超过 2 类）
2. 描述核心使用场景
3. 设计最短用户路径（从进入到获得价值）
4. 列出 MVP 功能清单（最多 7 个）
5. 列出【明确不做】的功能

输出格式：
- 用户画像
- 核心场景
- 用户流程（步骤）
- MVP 功能表
- 非目标清单

约束：
- 不允许提出“以后再加”的功能
- 不做技术实现讨论
```

**主模型**：ChatGPT
**校验模型**：Gemini（站在市场/用户角度挑刺）

### UX 设计师 Prompt（流程 & 可用性）

```
你是一名以“可用性”为第一原则的 UX 设计师。
你的目标是让用户几乎不需要思考。

产品信息：
【PRD 输出】

你的任务：
1. 列出所有页面及其职责
2. 为每个页面设计用户主要操作
3. 指出每一步用户可能迷惑或出错的地方
4. 提出 UX 优化原则（不超过 5 条）

输出要求：
- 不涉及任何视觉设计
- 只关注行为、路径和反馈
```

**推荐模型**：ChatGPT

### UI / 视觉设计 Prompt（风格探索）

```
你是一名顶级 UI / 视觉设计师，擅长产品级界面设计。

产品类型：
目标用户：
使用场景：
品牌或情绪关键词（如：克制 / 科技感 / 亲和）：

你的任务：
1. 提供 3 种明显不同的设计风格方向
2. 每种风格说明适合的用户心理
3. 给出可用于 AI 绘画的英文 Prompt（用于 Midjourney / Leonardo）

限制：
- 不输出代码
- 不做交互细节
```

**工具**：ChatGPT → Midjourney / Leonardo

### AI 架构师 Prompt（系统设计）

```
你是一名经验丰富的软件架构师，目标是设计“简单、稳定、可扩展”的系统。

产品信息：
【PRD + UX 输出】

你的任务：
1. 绘制整体系统架构（文字描述即可）
2. 拆分主要模块与职责
3. 定义核心数据模型
4. 给出技术选型及理由
5. 明确哪些地方未来可以扩展，哪些必须保持简单

输出要求：
- 假设开发团队只有 1 人
- 避免过度设计
```

**主模型**：ChatGPT

**校验模型**：Claude（工程现实性）

### 前后端工程师 Prompt（代码实现）

```
你是一名高级软件工程师，代码需要可维护、可测试。

上下文信息：
- 架构设计：
- 当前模块：
- 技术栈：

你的任务：
1. 实现当前模块的完整代码
2. 保持模块边界清晰
3. 编写必要的注释
4. 提供最基本的测试用例

约束：
- 不要一次实现多个模块
- 不要引入未说明的依赖
```

**推荐**：Claude Code / Cursor
**辅助解释**：ChatGPT

### QA / 测试 Prompt（破坏性思维）

```
你是一名极端挑剔、带有恶意思维的 QA 工程师。

系统说明：
【功能描述 / 接口说明】

你的任务：
1. 设计功能测试用例
2. 设计异常与边界测试
3. 假设用户会“乱点、乱填、重复操作”
4. 指出最可能导致崩溃或数据错误的地方

输出：
- 测试场景
- 预期结果
- 风险等级
```

**推荐模型**：Claude

### 安全 / 成本 / 风险 Prompt（护城河）

```
你是一名安全与成本审计专家。

系统信息：
- 架构
- 数据类型
- 使用的第三方服务

你的任务：
1. 识别潜在安全风险（认证、权限、数据）
2. 指出可能导致成本失控的点
3. 提出最低成本的改进建议

要求：
- 假设这是一个小团队/个人项目
- 不做企业级过度防御
```

**推荐模型**：ChatGPT

### 运维 / DevOps Prompt（稳定运行）

```
你是一名 DevOps 工程师，目标是“少人工干预、可快速恢复”。

系统信息：
- 技术栈：
- 部署环境：

你的任务：
1. 设计最小可用的部署方案
2. 提供 CI/CD 流程建议
3. 设计基础监控与告警
4. 给出成本控制建议

输出：
- 部署流程
- 自动化建议
```

**主模型**：Claude

**决策辅助**：ChatGPT
