# 中等规模 AI 平台硬件需求

## 一、先说关键认知

> 我们私有化部署的需求，本质是一个 **中等规模 AI 平台（Multi-Model + RAG + Agent + Vision）**。

跟算力中心对齐以下 4 点：

> 1️⃣ 我们是**推理为主（Inference-heavy）**，不是训练
> 2️⃣ QPS ≥ 10，是**稳定并发，不是偶发测试**
> 3️⃣ 模型类型多，**每类模型独立部署、独立扩容**
> 4️⃣ 我们关心的是：**单模型显存、并发能力、上下文长度、延迟，而不是“总算力”**

---

## 二、算力中心真正想知道什么？

### 为什么算力中心总是问你「需要多少 TFLOPS」？

#### 1、因为他们卖的不是“显卡”，而是“算力资产”

算力中心关心的是：
- 机房能提供多少 FLOPS / kW
- 调度系统如何把资源切片卖给不同客户
- 能否在一个集群里 混跑不同工作负载

**TFLOPS 是他们的“统一货币”。**

#### 2、显存 & 卡型，在他们眼里是“实现细节”

对算力中心来说：

- A100 / H100 / MI300X 都只是：
  - 算力密度
  - 功耗
  - 机柜占用
  - 网络拓扑

他们更关心的是：**“你这个 workload 吃多少算力时间？”**

而不是：**“你想怎么把显存塞满？”**

#### 3、但对「大模型推理客户」来说，这是信息不对称

关键差异：

| 视角         | 最关键的指标          |
| ------------ | --------------------- |
| 算力中心     | TFLOPS、功耗、机柜    |
| 大模型推理   | 显存、KV cache、通信  |

所以经常出现：
- 算力中心说：“算力够了”
- 一跑：OOM / 延迟爆炸 / QPS 上不去


他们问「需要多少算力」，**真正想要的是这些参数**：

| 维度     | 他们关心什么                          |
| ------ | ------------------------------- |
| GPU 型号 | A100 / H800 / H100 / L40 / A800 |
| 单卡显存   | 48G / 80G                       |
| GPU 数量 | 每个模型用几张                         |
| 并发     | QPS、最大并发                        |
| 精度     | FP16 / BF16 / INT8 / INT4       |
| 上下文    | 8k / 32k / 128k                 |
| 是否弹性   | 是否允许水平扩展                        |
| 是否常驻   | 7x24 还是按需                       |




## 三、给算力中心的【正式需求说明文档】

### 1. 项目背景说明

我们计划私有化部署多套开源大模型，用于公司的平台业务系统，主要场景包括：

* 模型对话（Chat / QA）
* RAG 知识检索（长文档）
* Agent 调用（规划 / 工具调用 / 推理）
* 图像识别（工业检测 + 多模态理解）
* 图像生成（后续阶段）

**整体特征**：

* 以 **推理（Inference）为主**
* 不涉及模型训练或微调（仅 LoRA 可能）
* 需要 **7×24 稳定服务**
* 最低目标 QPS：**10 QPS（每模型类型独立）**

---

### 2. 模型部署架构原则

* **不同模型类型独立部署**
* 每种模型单独一套 GPU 服务器
* 支持后续横向扩容
* 支持 vLLM / TensorRT-LLM / TGI 等推理框架

---

### 3. 各模型类型算力需求说明

---

#### A. 推理 / 规划 / Agent 主模型

##### 模型候选

* DeepSeek-V3.2（优先）
* GLM-4.7
* DeepSeek-R1-Distill-Llama-70B（备选）

##### 使用方式

* Agent 主模型
* 多轮对话
* 工具调用
* 推理链（CoT）
* 上下文：**32k – 64k**

##### 性能目标

* QPS ≥ 10
* 平均响应时间 < 2s（非极限）

##### 推荐算力配置（单模型实例）

| 项目     | 建议                  |
| ------ | ------------------- |
| GPU    | **A100 / H800 80G** |
| GPU 数量 | 预算充足 **24 卡（670B 级）** 或 预算不足**4 卡（70B~80B 级）**  |
| 显存占用   | 70–85%              |
| 精度     | BF16 / FP16         |
| 推理框架   | vLLM                |
| CPU    | ≥ 64 核              |
| 内存     | ≥ 512GB             |

> 这是 Agent 主模型，显存和上下文是瓶颈，不追求极致吞吐，但要稳定并发。

---

#### B. 文本处理 & 长上下文模型（RAG）

##### 模型

* Qwen3-Next-80B-A3B-Instruct

##### 使用方式

* 文档问答
* RAG 检索后生成
* 长上下文（64k~128k）

##### 性能目标

* QPS ≥ 10
* 支持长文本

##### 推荐算力配置

| 项目     | 建议                  |
| ------ | ------------------- |
| GPU    | **A100 / H800 80G** |
| GPU 数量 | **4–6 卡**           |
| 精度     | BF16                |
| 上下文    | ≥ 64k               |
| CPU    | ≥ 64 核              |
| 内存     | ≥ 512GB             |

> 这是**长上下文吞显存型模型**，比 Agent 更吃显存，不适合混部署。

---

#### C. 代码模型

##### 模型

* Qwen2.5-Coder-32B

##### 使用方式

* 代码生成
* 代码解释
* Agent 中作为子模型

##### 性能目标

* QPS ≥ 10
* 延迟敏感

##### 推荐算力配置

| 项目     | 建议                 |
| ------ | ------------------ |
| GPU    | **A100 / L40 48G** |
| GPU 数量 | **2 卡**            |
| 精度     | FP16 / INT8        |
| CPU    | ≥ 32 核             |
| 内存     | ≥ 256GB            |

---

#### D. 向量嵌入模型

##### 模型

* Qwen3-Embedding-8B
* （bge-m3 作为补充）

##### 使用方式

* 文档向量化
* 查询向量化
* 离线 + 在线混合

##### 性能目标

* 高吞吐
* 延迟 < 200ms

##### 推荐算力配置

| 项目     | 建议            |
| ------ | ------------- |
| GPU    | **L40 / A10** |
| GPU 数量 | **1 卡**       |
| 精度     | FP16 / INT8   |
| CPU    | ≥ 32 核        |
| 内存     | ≥ 128GB       |

📌 可以明确告诉算力中心：

> Embedding 是吞吐型，不需要大显存。

---

#### E. 图像识别 & 多模态理解

##### 模型

* DeepSeek-VL2 (small / full)
* Hunyuan-Vision-1.5
* YOLO / PP-YOLO（工业实时）

##### 使用方式

* 图像识别
* 多模态复核
* 工业检测

##### 性能目标

* 实时或准实时
* QPS ≥ 10（按业务）

##### 推荐算力配置

| 场景    | GPU       | 数量  |
| ----- | --------- | --- |
| 工业检测  | L40 / A10 | 1–2 |
| 多模态理解 | A100 80G  | 1–2 |

---

#### F. 图像生成（可选阶段）

##### 模型

* SDXL / 开源文生图模型

| GPU        | 数量  |
| ---------- | --- |
| L40 / A100 | 1–2 |

---

### 4. 总体资源拆分建议

| 模型类型       | GPU 卡数        |
| ---------- | ------------- |
| Agent 主模型  | 24 或 4             |
| 长文本 RAG    | 4–6           |
| 代码模型       | 2             |
| Embedding  | 1             |
| Vision     | 2             |
| **合计** | **27 ～ 39 GPU** 或 **13–15 GPU** |

---

### 5. 需要算力中心支持的能力

请算力中心确认是否支持：

* GPU 直通 / MIG
* NCCL 通信
* NVLink（70B 以上模型优先）
* 私有网络部署
* 容器化（Docker / K8s）
* GPU 监控与告警
